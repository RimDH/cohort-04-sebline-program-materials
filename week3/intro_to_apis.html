02 / APIS

What is an API?

API stands for Application Programming Interface. In web development, an API often lets one application request data or actions from another system.

APP

Your frontend

Your JavaScript asks for data.

API

Communication layer

Provides endpoints that accept requests.

DATA

Response

The API usually returns structured data such as JSON.

03 / JSON

What is JSON?

JavaScript Object Notation

JSON is a text format used to exchange structured data between systems.

  • Easy for humans to read
  • Easy for programs to parse
  • Very common in web APIs
{
  "name": "Sara",
  "age": 20,
  "isStudent": true
}
04 / JSON

JSON is similar to an object—but not the same

JAVASCRIPT OBJECT
const student = {
  name: "Sara",
  age: 20,
  active: true
};

Keys do not always need quotes. It exists directly in JavaScript memory.

JSON TEXT
{
  "name": "Sara",
  "age": 20,
  "active": true
}

Keys use double quotes. JSON itself is text sent between systems.

07 / JSON

Convert between JSON text and JavaScript

JSON → JAVASCRIPT
const jsonText = '{"name":"Sara","age":20}';

const user = JSON.parse(jsonText);

console.log(user.name);
JAVASCRIPT → JSON
const user = {
  name: "Sara",
  age: 20
};

const jsonText = JSON.stringify(user);
08 / HTTP

What is HTTP?

HTTP is the protocol used for communication between web clients and servers.

CLIENTBrowserCreates a request
→
HTTPRequestMethod + URL + headers + optional body
→
SERVERResponseStatus + headers + optional body
09 / HTTP

What is inside an HTTP request?

GET

Method

What kind of action do we want?

URL

Endpoint

Which resource are we requesting?

{ }

Optional data

Headers and sometimes a request body.

Note Headers describe the request or its content, while the body carries the data being sent
EXAMPLE GET https://jsonplaceholder.typicode.com/users
10 / HTTP

What comes back in a response?

200

Status code

Tells us whether the request succeeded or failed.

HDR

Headers

Metadata about the response.

JSON

Body

The returned content, often JSON.

12 / HTTP METHODS

GET — ask for data

Example request

Get a list of users from a public demo API.

  • No request body is normally needed
  • Data comes back in the response
GET /users

// Example with fetch:
fetch(
  "https://jsonplaceholder.typicode.com/users"
);
13 / HTTP METHODS

POST — send new data

Example

Create a new post by sending JSON in the request body.

fetch(
  "https://jsonplaceholder.typicode.com/posts",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      title: "Hello",
      body: "My first API request",
      userId: 1
    })
  }
);
14 / HTTP METHODS

Update and delete data

PUT

PATCH

Partial update

Send only the fields that need to change.

DELETE

Remove

Request deletion of a resource.

15 / STATUS CODES

HTTP status codes tell us what happened.

2xxSuccessThe request worked
4xxClient errorSomething is wrong with the request
5xxServer errorThe server failed while handling the request
16 / STATUS CODES

Status codes you should recognize

200OKSuccessful request
201CreatedA new resource was created
204No ContentSuccess, but no response body
400Bad RequestInvalid request data
401UnauthorizedAuthentication is required or invalid
403ForbiddenAuthenticated, but not allowed
404Not FoundThe resource does not exist
500Server ErrorThe server failed unexpectedly
17 / STATUS CODES

401 vs 403

401 — UNAUTHORIZED

Who are you?

The server requires valid authentication.

// Example:
No token
Expired token
Invalid credentials
403 — FORBIDDEN

You cannot do that

The server knows who you are, but you do not have permission.

// Example:
Student tries to access
an admin-only route
18 / REQUEST–RESPONSE LIFECYCLE

Follow one request from start

01JavaScript sends an HTTP request to an API endpoint.
02The request travels to the server.
03The server reads the method, URL, headers and body.
04The server processes the request and talks to a database.
05The server sends an HTTP response.
06JavaScript reads the response and updates the page.

20 / API DOCUMENTATION

How to read API documentation

01Find the base URL.
02Find the endpoint you need.
03Check the HTTP method.
04Check required parameters, query values or request body.
05Check authentication requirements.
06Read the example response and possible status codes.
21 / API DOCUMENTATION

Example documentation entry

DOCUMENTATION SAYS
Endpoint:
GET /users/{id}

Path parameter:
id — user ID

Example:
GET /users/3
YOUR JAVASCRIPT
const userId = 3;

const response = await fetch(
  `https://jsonplaceholder.typicode.com/users/${userId}`
);

const user = await response.json();

console.log(user.name);
22 / API DOCUMENTATION

Path parameters vs query parameters

PATH PARAMETER
/users/5

Usually identifies one specific resource.

QUERY PARAMETER
/posts?userId=5

Often used for filtering, sorting, searching or pagination.

23 / API DOCUMENTATION

What are HTTP headers?

Extra information about the request

  • Content-Type describes the body format
  • Authorization can carry credentials or tokens
fetch(url, {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify(data)
});
