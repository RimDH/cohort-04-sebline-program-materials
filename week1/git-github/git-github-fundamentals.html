05 / GET READY

Install and verify.

Install Git from git-scm.com and create an account on github.com.

Setup

  • Open VS Code and its terminal.
  • Run the command to confirm Git is installed.
  • A version number means Git is available.
git --version
06 / ONE-TIME SETUP

Tell Git who you are.

Configure identity

  • Use your own name and email.
  • These values identify the author of new commits.
  • For GitHub attribution, use an email verified on your account.
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

git config --global --list

08 / START TRACKING

Create a local repository.

Initialize

  • git init creates the hidden .git directory.
  • git status reports the current state of files.
  • Run these commands inside your project folder.
git init
git status

10 / INSPECT CHANGES

Check before you save.

Status

  • Untracked: new file Git has not added.
  • Modified: tracked file changed since last commit.
  • Staged: change prepared for the next commit.
git status
11 / SELECT CHANGES

Use git add.

Stage

  • git add stages changes; it does not create a commit.
  • Prefer selecting specific files when possible.
  • Review git status before committing.
git add index.html

# Or stage all changes in this folder:
git add .

git status
12 / SAVE A CHECKPOINT

Make your first commit.

Commit

  • A commit saves the staged snapshot locally.
  • Use a short, descriptive commit message.
  • A commit does not automatically upload to GitHub.
git commit -m "Create initial HTML page"
git status
13 / PRACTICE

Edit → stage → commit.

Repeat workflow

  • Change the heading or add a paragraph.
  • Inspect the change.
  • Create a second meaningful checkpoint.
# Edit index.html and save it
git status
git add index.html
git commit -m "Add about section"
14 / SEE YOUR WORK

Explore your history.

History

  • git log --oneline lists recent commits.
  • git diff shows unstaged edits.
  • git diff --staged shows what will be committed.
git log --oneline

# See unstaged line changes:
git diff

# See staged line changes:
git diff --staged
15 / KEEP THE REPO CLEAN

Use .gitignore.

Ignore files

  • Create a file literally named .gitignore.
  • Ignore generated files and local secrets.
  • Never commit passwords, tokens, or API keys.
  • Already tracked files are not automatically untracked.
# .gitignore
node_modules/
.env
dist/
.DS_Store
16 / EXPLAIN THE PROJECT

Write a useful README.

README

  • Save it as README.md in the project root.
  • Describe the purpose and how to run the project.
  • Stage and commit the README.

## How to run

18 / LINK LOCAL AND ONLINE

Connect to origin.

Connect remote

  • Replace USERNAME with your GitHub username.
  • Copy the HTTPS URL from your new repository.
  • origin is the conventional nickname for the remote.
git branch -M main
git remote add origin https://github.com/USERNAME/my-first-site.git
git remote -v
19 / UPLOAD YOUR WORK

Publish with git push.

Push

  • Uploads local commits to GitHub.
  • You may need browser or credential-manager authentication.
  • A GitHub account password is not used for Git HTTPS authentication.
  • Refresh GitHub to see your files.
git push -u origin main
20 / THE BASIC ROUTINE

Edit, commit, push.

Daily cycle

  • Edit and save your project files.
  • Check what changed before staging.
  • Commit locally, then push to GitHub.
git status
git add .
git commit -m "Improve homepage"
git push
21 / GET AN ONLINE PROJECT

Download with git clone.

Clone

  • Clone creates a local copy of an existing repository.
  • Use clone when starting from a repository on GitHub.
  • Do not run git init again inside the cloned project.
git clone https://github.com/USERNAME/my-first-site.git
cd my-first-site
git status
22 / KEEP A COPY UPDATED

What does git pull do?

Pull basics

  • Downloads and integrates remote changes into the current branch.
  • Useful after editing a file directly on GitHub.
  • Commit or otherwise handle local changes before pulling if they may conflict.
git pull origin main
23 / TROUBLESHOOTING

Know the common errors.

!

Open the correct folder or initialize Git.

!

Nothing to commit

!

Authentication failed

Sign in using the supported GitHub authentication flow.

24 / CHEAT SHEET

Commands to remember.

Quick reference

  • Git manages your local history.
  • GitHub hosts your remote repository.
git init             # Start a repository
git status           # Inspect changes
git add .            # Stage changes
git commit -m "..."  # Save snapshot
git log --oneline    # View history
git remote -v        # Show remote URL
git push             # Upload commits
git clone URL        # Copy repository
